# The app in English and Spanish

**Status:** in progress (Oct 5, 2026) · **Owner:** Cristian

## Why

Corteza's first customers speak Spanish. Outcomes already follow each meeting's language and the morning partner has its own Spanish voice, but the screens were English only.

## Decisions (Oct 5)

- **Bilingual, per person.** The language is what the person picked in Settings (`workspace_members.language`), else their browser's (`Accept-Language`: any Spanish variant → Spanish), else English.
- **No external service** (no live-translation widget: it would send outcome text to a third party, and the CSP blocks third-party scripts; no translation platform until there are human translators or more languages).
- **One dictionary per language,** `public/i18n/<lang>.json`, nested by area. The same files serve the server (pages, emails) and the browser. A test fails CI when a key is missing in a language or a page uses a key that doesn't exist.
- **Our own small `t()`** (no library, the app has no build step): `{placeholders}`, plural forms (`one`/`other`, plus `zero`) picked with `Intl.PluralRules`, dates with `toLocaleDateString(CortezaI18n.locale)`.
- **Glossary and tone** are in the design skill (`.claude/skills/corteza-design/SKILL.md`, "Languages"). Tú, neutral Latin American Spanish, no gendered adjectives for the reader.

## How it works

- `src/core/i18n/i18n.js`: `translate(lang, key, vars)`, `requestLanguage(req)`, `localizeHtml(html, lang)`, `localizedPage(html)`.
- Pages: static text is written `{{t:key}}` in `src/views` (`{{tu:key}}` inside a URL). Each page is rendered once per language at startup (`localizedPage`), with `<html lang>` set and the dictionary added before `</head>` (`window.__CORTEZA_I18N__` plus `public/scripts/i18n.js`, which defines `t()` and `CortezaI18n`).
- Scripts: `t('key', vars)` returns plain text; escape it before `innerHTML`.
- Settings → Language: `GET`/`PUT /api/me/language` (`src/http/language.js`, `src/core/users/language.js`). The pick is copied into the session at sign-in and when saved.
- Preview: `node .claude/skills/corteza-design/scripts/preview.js --lang es`.

## Plan

1. **Base and what people see every day** (this PR): the i18n core, the language picker, the sidebar, Home (both tabs, the Log manually, edit, delete and upload modals), the outcome detail modal, review controls and onboarding.
2. **The other pages:** Action items, Questions & risks, Search, Settings, Login, and the close-the-loop prompts.
3. **Emails** in the recipient's language: morning summary, welcome, import summary, weekly digest.
